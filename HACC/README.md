# HACC Generator & Deployment

Converts a Bambu-generated `top_level.v` into a complete Vitis/HACC deployment folder,
builds it on `hacc-build-01`, and runs it on a booked Alveo U55C node.

---

## End-to-end workflow

```bash
# 1. Generate deploy folder from Bambu Verilog
python3 generate_hacc_project.py \
    --verilog path/to/top_level.v \
    --workload conv --dims 4 4 4 4 3 3
DEPLOY=$(ls -td [0-9]*/ | head -1 | tr -d '/')

# 2. Generate input data (once per design)
python3 gen_inputs.py $DEPLOY/input_data

# 3. Build on hacc-build-01 (~4-8h for hw)
bash deploy_and_run.sh build $DEPLOY

# 4. (Optional) Fetch Vivado .rpt files after build, before running on alveo
bash deploy_and_run.sh fetch-reports $DEPLOY

# 5. Run on alveo + collect results + verify (input_data auto-found in $DEPLOY/input_data)
bash deploy_and_run.sh run $DEPLOY hacc-alveo-u55c-01

# 6. Performance analysis (run.log + Vivado .rpt → perf_*.txt in $DEPLOY/)
bash performance_analysis.sh $DEPLOY/run.log
```

`deploy_and_run.sh run` runs steps 5 and 6 automatically. Run step 6 manually only
if you want to re-generate the perf report without re-running the accelerator.

| Requirement | Details |
|-------------|---------|
| Python 3.8+ | Standard library only |
| `lib/panda_libtech.v` | Bambu stdlib — place here once, generator copies it into every deploy |

| Bambu `top_level.v` | Generated by PandA-Bambu from C source |

### Test utilities (HACC root)

| File | Purpose |
|------|---------|
| `gen_inputs.py` | Generate banked float32 inputs + golden reference |
| `verify.py` | Compare accelerator outputs against golden reference; reports PASS/FAIL |
| `performance_analysis.sh` | Parse `run.log` + Vivado `.rpt` files → `perf_*.txt` with wall-clock times, real kernel clock, and resource utilization |

## CLI arguments

| Argument | Default | Description |
|----------|---------|-------------|
| `--verilog` | *(required)* | Path to Bambu `top_level.v` |
| `--output` | `HACC/<timestamp>/` | Output directory (created if absent) |
| `--platform` | `xilinx_u55c_gen3x16_xdma_3_202210_1` | Vitis platform string for the target board |
| `--target` | `hw` | `hw_emu` for emulation, `hw` for real FPGA |
| `--hbm-bank` | `HBM[0]` | HBM bank for all AXI masters (edit `xo_to_xclbin.sh` for per-port banking) |
| `--workload` | *(none)* | `conv` or `gemm` — adds workload dims to `accel_config.json` |
| `--dims` | *(none)* | Workload dims: `M P Q C R S` (conv) or `M K N` (gemm) |

## Generated structure

```
<output>/
├── src/
│   ├── top_level.v              ← Bambu core (copied unchanged)
│   ├── panda_libtech.v          ← Bambu stdlib (copied from lib/)
│   ├── top_level_translator.v   ← AXI-Lite control slave (generated)
│   └── panda_wrapper.v          ← Vitis top module, kernel: "panda" (generated)
├── host/
│   ├── CMakeLists.txt
│   ├── UserConfig.cmake
│   └── src/harness.cpp          ← XRT host application
├── build/                       ← Created during build (not in source)
│   ├── vpp/logs|tmp|reports     ← v++ intermediate files + Vivado .rpt files
│   └── host/bambu_application   ← Compiled host binary
├── xo/
│   ├── panda.xo                 ← Created by Vivado
│   └── panda.xclbin             ← Created by v++
├── input_data/                  ← Binary inputs (generated by gen_inputs.py)
├── output_data/                 ← Binary outputs (written by bambu_application on alveo)
├── script_to_xo.tcl             ← Vivado: packages src/ as panda.xo
├── xo_to_xclbin.sh              ← v++: links panda.xo → panda.xclbin
├── build_all.sh                 ← Full build pipeline (Vivado + v++ + cmake)
├── accel_config.json            ← Buffer layout for harness.cpp
├── xrt.ini                      ← XRT profiling config (copied from lib/)
├── run.log                      ← Copied back from alveo after run
└── perf_<timestamp>.txt         ← Generated locally by performance_analysis.sh
```

## Performance numbers and clock reality

The harness prints:
```
[perf] Est. kernel cycles : 109200  (@ 300 MHz)
```

This is a rough estimate using the target clock. The real post-route clock is lower
due to Worst Negative Slack (WNS). `performance_analysis.sh` reads the Vivado timing
report and shows the true frequency:

```
Actual freq  : 154.4 MHz   ← 1000 / (target_period_ns − WNS_ns)
Kernel cycles: ~56202       ← kernel_ms × 154.4 MHz × 1000
```

**APM hardware profiling caveat:** Adding `--profile_kernel data:all:all:all` to
`xo_to_xclbin.sh` embeds APM counters in the bitstream. For large designs (n=96 PE
eyeriss), this pushes routing over its limit (128k+ node overlaps → routing failure).
Do not add profiling flags to large designs. The Vivado timing report gives accurate
cycle counts without any routing overhead.

**Power:** Vivado's v++ flow does not write `impl_1_power_routed.rpt` by default,
so power shows N/A in the perf report. This is expected.

## How the generator works

`generate_hacc_project.py` (entry point) calls `hacc_gen/cli.py`:

```
top_level.v
    │
    ├─ parser.py          parse_interface()
    │      Reads port declarations, identifies scalar args,
    │      AXI master bundles, and buffer sizes.
    │      Returns an Interface object.
    │
    ├─ gen_translator.py  gen_translator_v()
    │      Generates an AXI-Lite slave that maps s_axi_control
    │      registers to scalar wire outputs (ap_start, scalars).
    │
    ├─ gen_wrapper.py     gen_wrapper_v()
    │      Generates panda_wrapper: the Vitis-visible top module
    │      that instantiates the translator + Bambu top_level.
    │      Handles ap_start pulse conversion and ap_done/ap_ready.
    │
    ├─ gen_tcl.py         gen_script_to_xo()
    │      Generates script_to_xo.tcl: creates a Vivado project,
    │      packages src/ as a Vitis IP, and calls package_xo.
    │
    │                     gen_xo_to_xclbin()
    │      Generates xo_to_xclbin.sh: runs v++ link with
    │      --connectivity.sp entries for all AXI master ports.
    │
    │                     gen_build_all_sh()
    │      Generates build_all.sh: sets up Vivado/Vitis/XRT
    │      environment on hacc-build-01 and runs all 3 steps.
    │
    ├─ gen_host.py        gen_harness_cpp(), gen_cmake(), gen_user_config_cmake()
    │      Generates XRT host application + CMake build files.
    │      harness.cpp reads accel_config.json at runtime to know
    │      which .bin files to load and which are input vs output.
    │
    └─ gen_config.py      gen_accel_config()
           Generates accel_config.json: one entry per AXI buffer
           with name, size_bytes, direction, group_id, and axi_bundle.
```

### Key design decisions

**Kernel name `panda`** — hardcoded in `panda_wrapper.v`, `script_to_xo.tcl`, and `harness.cpp`. All three must agree.

**`ap_ctrl_hs` protocol** — Bambu generates a pulse-based `start_port`; the wrapper converts the level signal from the AXI-Lite slave into a 1-cycle pulse. `ap_ready` fires one cycle after `start_port`.

**AXI-Lite address map** — scalar args start at offset `0x10`, spaced `0x08` apart. `CTRL` is at `0x000` (required by `ap_ctrl_hs`).

**HBM banking** — AXI master ports are mapped to separate HBM banks (`HBM[0]`–`HBM[7]`) for parallel bandwidth. The generator assigns one bank per bundle in order; edit `xo_to_xclbin.sh` to adjust.

**XRT env workaround** — `xrt_2024.2/setup.sh` on hacc-build-01 rejects paths not ending in `/xrt`. `build_all.sh` sets `XILINX_XRT`, `LD_LIBRARY_PATH`, `PATH`, and `PYTHONPATH` manually instead of sourcing `setup.sh`.
